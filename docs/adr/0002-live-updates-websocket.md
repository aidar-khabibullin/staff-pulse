# ADR 0002: WebSocket для live-обновлений вместо SSE или поллинга

## Контекст

Задание требует канал live-обновлений орг-структуры на выбор: WebSocket, SSE или эффективный поллинг (с учётом частоты изменений, backoff, минимизации лишних запросов). Обновления частые (по умолчанию раз в секунду) и двусторонний обмен не нужен — сервер только рассылает патчи, клиент их только принимает.

## Решение

Реализован WebSocket-канал: `GET /ws/org-tree` на FastAPI (`server/app/main.py`, `server/app/live_updates.py`) с фоновой asyncio-задачей в `lifespan`, которая раз в `LIVE_UPDATE_INTERVAL_SECONDS` мутирует случайный узел и рассылает патч всем подключённым клиентам через `ConnectionManager.broadcast`. На клиенте — `useOrgTreeLiveUpdates` с явным статусом соединения (`connecting`/`open`/`reconnecting`/`closed`) и переподключением с экспоненциальным backoff (1с → ×2 → максимум 30с при обрыве).

## Альтернативы

- **SSE (Server-Sent Events).** Технически подошёл бы (однонаправленный поток, есть встроенный auto-reconnect у `EventSource`), но: (1) через Nginx-прокси в Docker потребовал бы отдельной настройки буферизации/таймаутов, аналогичной WebSocket-апгрейду, то есть не даёт выигрыша в простоте; (2) `EventSource` не поддерживает кастомные заголовки и сложнее тестировать в Playwright по сравнению с обычным WS-клиентом; (3) собственный backoff всё равно пришлось бы писать вручную для соответствия критерию «индикатор соединения + экспоненциальный backoff», так что встроенный reconnect `EventSource` не экономит код.
- **Поллинг с интервалом.** Отклонено: при обновлении раз в секунду поллинг с сопоставимой частотой создаёт HTTP-запрос на каждый тик независимо от того, изменилось ли что-то, что прямо противоречит требованию «минимизация лишних запросов»; WebSocket отправляет данные только когда есть реальное изменение.
- **Поллинг с длинным интервалом + ETag/If-Modified-Since.** Снизил бы задержку обновления UI до величины интервала и всё ещё требует ручного backoff при ошибках сети — не даёт видимого преимущества перед WebSocket при этой частоте изменений.

## Последствия

- Nginx (`client/nginx.conf`) должен явно проксировать `/ws/*` с заголовками `Upgrade`/`Connection` — учтено в Фазе 7.
- Клиент обязан сам реализовывать переподключение и backoff (WebSocket не даёт этого «из коробки», в отличие от `EventSource`) — реализовано в `useOrgTreeLiveUpdates`.
- Формат патча сознательно минимален (`{ id, changes, updatedAt }`, только изменившиеся поля) — экономит трафик и позволяет клиенту делать частичный пересчёт агрегатов вместо полного рефетча (см. [data-model.md](../data-model.md#контракт-live-патча)).
