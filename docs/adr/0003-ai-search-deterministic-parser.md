# ADR 0003: Детерминированный клиентский парсер вместо внешнего LLM API для AI-поиска

## Контекст

Фаза 8 требует AI-поиск: строка поиска принимает запрос на естественном языке, ответ — структурированный фильтр на клиенте, при неуспехе — текстовый fallback. Проект — тестовое задание без backend-прокси к внешнему AI-провайдеру и без API-ключа в репозитории; Фаза 8 по объёму работ — только frontend (изменений на сервере не предполагалось).

## Решение

Реализован детерминированный клиентский NLP-парсер `parseNaturalLanguageQuery` (`client/src/features/ai-search/model/`), который разбирает ограниченный, но покрывающий типовые запросы набор паттернов на русском языке («эффективность выше 80», «уровень 2», «второй уровень», «бюджет больше 5 000 000», «сотрудников не менее 10» и т.п.) в структурированный фильтр `{ text, level, metric }`. Фильтр применяется и к дереву (`pruneTree` — сохраняет путь предков до совпадений, авто-раскрывает их), и к таблице (`applyStructuredFilter`, AND с текстовым фильтром колонки). Если ни один паттерн не распознан — явный fallback на обычный текстовый поиск по названию, с индикатором активного режима в UI (`AiSearchBar`).

## Альтернативы

- **Реальный вызов LLM API (например, через backend-прокси к Anthropic/OpenAI).** Отклонено: требует секретного API-ключа, сетевого backend-компонента вне заявленного скоупа Фазы 8 (только frontend) и вносит внешнюю зависимость с задержкой и стоимостью запроса в критический путь поиска — избыточно для ограниченного набора структурированных фильтров, которые нужно извлечь (текст/уровень/метрика с оператором и числом).
- **LLM API с ключом пользователя, вводимым в UI.** Отклонено: хранение и передача ключа на клиенте — риск безопасности и не то, что ожидается от тестового задания; также усложняет проверку задания без собственного ключа проверяющего.
- **Полный отказ от AI-поиска, оставить только текстовый фильтр.** Отклонено: не выполняет явное требование критерия готовности «AI-поиск принимает запрос на естественном языке и возвращает структурированный фильтр».

## Последствия

- Парсер работает только с ограниченным набором паттернов на русском — не является LLM в полном смысле и не обобщается на произвольные формулировки; это компромисс, документированный в README («Что сгенерировано», Фаза 8) и здесь.
- Нет сетевой задержки и внешней зависимости — фильтр применяется мгновенно, что упрощает и Playwright-тесты (нет необходимости мокать сетевой AI-вызов).
- При появлении реального backend AI-провайдера в будущем — точка расширения: `parseNaturalLanguageQuery` можно заменить на асинхронный вызов, сохранив контракт возвращаемого структурированного фильтра `{ text, level, metric }` и существующий fallback-путь.
