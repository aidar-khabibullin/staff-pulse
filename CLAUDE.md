# CLAUDE.md

Рабочие правила для Claude Code в этом репозитории. Задание и требования — в [README.md](README.md); PRD — в [docs/prd-org-structure-dashboard.md](docs/prd-org-structure-dashboard.md); план фаз — в [docs/plan-org-structure-dashboard.md](docs/plan-org-structure-dashboard.md).

## О проекте

Дашборд мониторинга орг-структуры компании: иерархия дивизионы → отделы → команды, интерактивное дерево, аналитическая таблица с агрегированными показателями, live-обновления, AI-поиск. Тестовое задание, обязательное условие которого — использование AI-инструментов в разработке с фиксацией этого в README.

## Стек

- **Backend** (`server/`): Python, FastAPI, uvicorn, pytest
- **Frontend** (`client/`, появится в Фазе 2): Vite, React, TypeScript
- **E2E**: Playwright, конфиг и тесты в корне репозитория (`playwright.config.ts`, `e2e/*.spec.ts`)

## Структура репозитория

```
server/   — mock API сервер (Фаза 1)
client/   — frontend (с Фазы 2)
e2e/      — Playwright-тесты (project "api" — HTTP-контракты, "ui" — браузерные сценарии)
docs/     — PRD, план фаз, architecture.md, data-model.md, adr/ (появятся по ходу)
```

## Правила ведения работы (обязательно соблюдать)

1. **Ветки.** Каждая фаза реализуется в отдельной ветке `phase/N-<slug>` от `main`, мержится обратно через `git merge --no-ff`. Инфраструктурные изменения, не привязанные к одной фазе — в `chore/<slug>`.
2. **Закрытие фазы.** При завершении фазы: отметить все её задачи как `- [x]` и добавить `— ✅ выполнена` в заголовок фазы в `docs/plan-org-structure-dashboard.md`, закоммитить это вместе с остальными изменениями фазы (или отдельным `docs:`-коммитом сразу после мержа).
3. **Теги коммитов.** `step/N` ставятся по карте из `docs/plan-org-structure-dashboard.md`: Фазы 1–3 → `step/1`, Фаза 4 → `step/2`, Фазы 5–6 → `step/3`, Фазы 7–9 → `step/4`.
4. **Playwright на каждой фазе.** Каждая фаза добавляет минимум один Playwright-тест, покрывающий её критерий готовности («Когда готова» в плане). `ui` project подключается в Фазе 2 вместе с `client/`.
5. **README «AI в разработке».** Обязательный раздел — обновлять при каждой фазе: что сгенерировано ассистентом, что переписано руками и почему.
6. **Коммиты.** Только по явному запросу пользователя (см. системные инструкции); не коммитить самостоятельно без запроса в рамках диалога, если это не часть уже согласованного процесса закрытия фазы.

## Тесты

```bash
# Backend unit-тесты (pytest, из активированного venv в server/)
cd server && source .venv/bin/activate && pytest

# E2E (Playwright, из корня репозитория)
npm run test:e2e
```
